# CLAUDE.md

Kathalu iOS — native SwiftUI port of the Kathalu web app (Telugu reading practice:
stories, tap-to-learn words, SM-2 flashcards, script lessons). See `README.md` for the
feature/structure overview and **`ROADMAP.md` for what to build next** — work here is
roadmap-driven, and shipped features get marked ✅ Done there with short as-built notes.

## Build & verify

`xcode-select` points at CommandLineTools, so `xcodebuild` needs a `DEVELOPER_DIR` prefix:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  /Applications/Xcode.app/Contents/Developer/usr/bin/xcodebuild \
  -project Kathalu.xcodeproj -scheme Kathalu \
  -destination 'platform=iOS Simulator,id=171632C6-2345-4D26-A271-D60B47AD3092' build
```

(That UDID is the local iPhone 17 Pro simulator.)

- **Compile-check only by default. Never launch or screenshot the simulator to see how
  something looks without asking first.** The user tests behavior/appearance on their own
  device and sends screenshots — that's the preferred way to check UI. `xcodebuild … build`
  (compile check) is always fine; installing, launching, or screenshotting a simulator is
  not. If you genuinely think you need to run it yourself (e.g. memory sampling, reproducing
  a runtime crash), **ask first and list exactly what you'd check** so the user can decide
  whether to just send screenshots instead.
- The project uses `PBXFileSystemSynchronizedRootGroup` (objectVersion 77): new files
  anywhere under `Kathalu/` join the app target automatically, and new files under
  `KathaluWidgets/` join the widget extension — never edit `project.pbxproj` to add files.
  The one exception: an app file the widget also needs must be listed in the
  `Exceptions for "Kathalu" folder in "KathaluWidgetsExtension"` set's
  `membershipExceptions` (that's what Xcode's Target Membership checkbox writes).
- Building the `Kathalu` scheme also builds the embedded `KathaluWidgetsExtension`.
- There is no test target.

### DEBUG launch hooks (simctl launch args)

`-openTab <tab>` · `-openStory <idx>` · `-openDeck vowels|consonants|guninthalu|vatthulu`
(selects a deck in the **Review** tab) · `-ttsStress 1` (10k-utterance TTS loop for leak hunting).

## Architecture — the rules that aren't obvious from the code

- Single `@Observable @MainActor` **`AppModel`** injected via `.environment(AppModel.self)`;
  views use `@Environment` + `@Bindable`. Tabs: **Read** (LibraryView) / **Learn** / **Review**
  / **Profile**. IA rule: **Learn = acquire** (its segments are Journey / Charts / Write — no
  SRS drill decks), **Review = retain** (the single "due today" inbox: story vocab + the four
  script decks). Progress is a pushed detail inside Profile, not a tab.
- **`SM2.schedule` must match the FastAPI backend's math exactly** — don't touch scheduling;
  add metadata around it instead.
- **Two persistence worlds, kept separate on purpose:**
  - `UserData` (`userdata.json` via `LocalStore`) — vocab cards, streaks, progress. Synced
    write-through by `SyncEngine` when signed in. **Sign-in rebuilds `UserData` from the
    server**, so any field the backend doesn't know about will be wiped.
  - Script-deck SM-2 state (`aksharacards.json` via `AksharaStore`) — deliberately outside
    `UserData` for that reason; local-only. Keys are namespaced: bare letter,
    `gunintha:<vowel>`, `vatthu:<letter>`.
- Simple settings (sound toggle, `speechVoiceID`, `speechRate`, appearance, font size) are
  UserDefaults-backed via `didSet` on AppModel properties. `didSet` doesn't fire during
  init — push loaded values into services at the **end** of `init` (after `sync` is set).
- Script data lives in code (`Models/Akshara.swift`), not JSON. Composite forms are
  **generated**, never tabulated: guninthalu = consonant + mātra, vatthulu/conjuncts =
  base + virama (్) + consonant. `Akshara.spoken` overrides TTS for glyphs the te-IN
  voice mispronounces (e.g. ౠ → "రూ") — extend that mechanism when the user reports a
  bad pronunciation.
- Meanings come from the bundled `Resources/dictionary.json` via `DictionaryService`
  (MyMemory is only a fallback). **Don't hand-edit that file** — it's generated by
  `tools/glossary/export_dictionary.py` from `tools/glossary/drafts/` + `reviews.json`;
  fix meanings in the drafts and re-export. New story text → new word forms to draft
  (`tools/glossary/new_forms.py <idx>`).
- `SpeechService` is the only TTS path; it applies the user's voice/rate per utterance.
  Prefer speaking whole words over bare syllables — the voice handles context better.

## Widgets & Live Activity

- `Kathalu/Shared/WidgetShared.swift` is the app↔extension contract (member of both
  targets): App Group `group.me.kathalu.app`, snapshot keys, widget kinds, deep links,
  `FlashcardSnapshot`, `ReadingActivityAttributes`. **Never rename a shipped widget kind**
  — users' placed widgets would disappear.
- The app writes only raw data (`readDays`, `storyBest`, deck `flashcards`) via
  `AppModel.refreshWidgets()`, called from `persist()`; it reloads only the kinds whose
  data changed. Widgets compute anything time-based themselves (streak, today's story,
  letter of the day) so they stay right past midnight without the app running.
- Random picks (word, sentence) are a pure function of the time slot (`SlotPicker`), so a
  reload never reshuffles what's on screen. Don't use `hashValue`/`randomElement` there.
- Shared app files the extension compiles: Akshara, Story, VocabCard (DayStamp),
  StoryStore, Transliterator, WidgetShared, plus stories.json and the Noto fonts.
- Deep links (`AppModel.handleDeepLink` → tab): `kathalu://story/<idx>`,
  `kathalu://review`, `kathalu://letter/<letter>`.
- The Flashcard widget grades for real but **never wakes the app** (that cost seconds
  per tap): Hard/Good (`GradeFlashcardIntent`, widget process) only log to the App Group
  (`FlashcardGrades`) and the widget hides logged cards. The app applies the log at
  launch/foreground via `AppModel.applyWidgetGrades` → `rate` (same SM-2 path + sync).
  Its queue mirrors the Review tab's session order.
- `persist()` writes `userdata.json` off the main thread and debounces
  `refreshWidgets()` (~1.5 s, flushed on background) — keep per-tap work cheap.
- The reading Live Activity (`ReadingActivityController`) starts when `ReaderView`
  appears, updates when it's backgrounded or finished, ends on dismiss. iPhone only.
- The widget target's deployment target must match the app's (iOS 18.0); a newer value
  silently hides the widgets on older devices.

## UI conventions

- All colors/fonts come from `Theme` (`Theme.serif` for Telugu, `Theme.latinSerif` for
  romanizations, `Theme.sans`); match existing tiles, sheets, DeckRow, and card-stack
  patterns before inventing new ones. New screens should look like they were always there.
- **Sheet detent gotcha:** present detail drawers with `.sheet(isPresented:)` plus a
  separate selection `@State` (clear it in `onDismiss`), never `.sheet(item:)` — an item
  change re-presents the sheet and resets a compact detent to full height. Pair with
  `.presentationBackgroundInteraction(.enabled(upThrough:))` so charts stay browsable.
- Review-session views (`AksharaReviewView`, `GuninthaluReviewView`, `VatthuluReviewView`)
  take an `embedded` flag so the Review tab's deck picker can host them without their own
  navigation chrome; keep that pattern for new decks.
- Speak only when `model.soundEnabled`; put a `SoundToggleButton` in the toolbar of any
  new screen that talks.

## Known landmines (details in ROADMAP.md Part 2)

- `SyncEngine` is not `@Observable` — the Profile sync pill doesn't live-update.
- `ReaderView.pages` re-paginates on every render (cheap at current story sizes).
- Reader token ids are story-wide `paragraph-offset` — keep them independent of
  pagination. Story completion needs the end reached *and* `minimumReadSeconds`.
- Stories have a **level** (`StoryLevel`, 1–4 by word count; `"level"` in stories.json
  overrides). `AppModel.currentLevel` only rises; it's mirrored to the App Group and
  `StoryStore.index(for:)` picks today's story from that level — so the app, widgets and
  reminders agree. **Adding a story** also means drafting its new word forms for the
  glossary (`tools/glossary/new_forms.py <idx>`) and re-exporting the dictionary.
- Daily reminders (`NotificationService`) schedule 14 individual days, not a repeating
  trigger — call `AppModel.rescheduleReminders()` after anything that changes the streak
  or today's read state. Settings live in UserDefaults (`reminderEnabled`/`reminderMinute`).
- Resume positions are story-wide paragraph indexes in UserDefaults (`readingPositions`),
  local-only like script-deck state.
- The story-vocab deck holds only words added via "Add to flashcards" (a tap just counts
  in `wordTaps`). Reviews are capped at `AppModel.dailyReviewCap` (20/day) — use
  `todaysReviewQueue`/`dueCount`, not raw `isDue`, for anything user-facing. Delete cards
  with `removeCards` (syncs + survives sign-in via `pendingCardDeletes`).
- The streak counts a day after `AppModel.dailyReadingGoal` (3 min) of active reading,
  not on story completion.
